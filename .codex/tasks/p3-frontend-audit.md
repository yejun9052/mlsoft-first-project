# 작업: 프론트엔드 실사용 결함 전수 조사 (F-1 / F-5 / F-6 / mock 잔존)

`docs/10-코드리뷰-리포트.md`의 F 섹션을 지금 코드 기준으로 실측해라. 고치지는 말고 목록만 낸다.

## 1. F-6 — `isError` 미처리 (무한 스피너)

`frontend/src/pages/` 전체를 훑어라. 각 페이지가 쓰는 React Query 훅마다:

| # | 페이지:줄 | 쿼리 훅 | `isLoading` 처리 | `isError` 처리 | 실패 시 화면 |
|---|---|---|---|---|---|

"실패 시 화면"은 실제로 무엇이 보이는지 써라 — `무한 스피너` / `빈 상태(오류인데 '없습니다')` /
`빈 화면` / `정상 안내` 중 하나로 판정한다.

**둘째가 더 위험할 수 있다** — 오류인데 "데이터가 없습니다"라고 보이면 사용자가 잘못된 결론을 내린다.
`empty={...}` 판정에 `isError`가 안 섞여 있는 곳을 특히 찾아라.

`components/ui/`에 이미 있는 상태 컴포넌트(`LoadingState`, `EmptyState`, `TableCard`의 loading/empty
props 등)를 확인하고, **오류 상태를 표현할 컴포넌트가 있는지** 판정해라. 없으면 그렇게 써라.

## 2. F-1 — 쿼리 키에 파라미터 누락

`frontend/src/hooks/use*.js` 전부를 읽고, **쿼리 함수에 넘기는 인자 중 쿼리 키에 빠진 것**을 찾아라.

| # | 훅 파일:줄 | 쿼리 키 | queryFn에 넘기는 인자 | 키에 빠진 인자 | 증상 |
|---|---|---|---|---|---|

`size`·`status`·`action`·`page` 같은 것이 키에 없으면 서로 다른 파라미터의 결과가 같은 캐시를
공유해 **먼저 캐시된 응답이 그대로 재사용된다**. 어떤 화면에서 어떻게 잘못 보이는지 구체적으로 써라.

## 3. F-5 — invalidate 누락

각 뮤테이션 훅이 성공 후 무효화하는 키와, 그 변경으로 **실제로 바뀌는 다른 쿼리**를 비교해라.

| # | 뮤테이션 파일:줄 | 무효화하는 키 | 무효화해야 하는데 빠진 키 | 증상 |
|---|---|---|---|---|

예: 연차를 신청하면 잔여 요약·대시보드·캘린더가 같이 바뀌는데 목록만 무효화하는 경우.

## 4. mock 잔존 사용처

`frontend/src/mocks/data.js`를 import하는 파일을 전부 찾아 표로:

| # | 파일:줄 | import하는 것 | 대체할 실 API가 있는가 | 근거 |
|---|---|---|---|---|

"대체할 실 API가 있는가"는 `frontend/src/api/*.js`와 백엔드 컨트롤러를 실제로 확인해서 판정해라 —
`ApprovalsPage.jsx:5`의 주석은 "API가 없다"고 하는데 그 주석이 지금도 맞는지 검증할 것.

## 5. 처리 완료 탭을 실 API로 바꿀 때 부족한 필드

`ApprovalsPage`의 processed 모드 행이 쓰는 필드와 `LeaveHistoryLogResponse`가 주는 필드를 대조해라.

| 화면이 쓰는 필드 | 응답에 있는가 | 없으면 대안 |
|---|---|---|

특히 `기간`(신청 날짜 범위)이 응답에 있는지 확인하고, 없으면
`LeaveActionHistoryRepository`의 `@EntityGraph` 설정을 보고 **`dates`를 추가할 때 N+1이 생기는지**
판정해라.
