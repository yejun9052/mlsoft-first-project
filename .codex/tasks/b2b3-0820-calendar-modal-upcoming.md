## B-2 — 캘린더 하루 상세 모달

한 날짜에 항목(연차·개인 일정·공휴일)이 많이 몰리면 **셀 안에서 다 못 보여준다.**
그 날짜를 눌러 **한눈에 볼 수 있는 모달**을 붙인다.

- 셀에는 지금처럼 몇 개만 보이고, 넘치면 **"+N개"** 같은 여는 손잡이를 둔다.
  몇 개까지 셀에 둘지는 **네가 정하고 근거를 써라**(셀 높이가 들쭉날쭉해지면 안 된다)
- 모달에는 그날의 **연차·개인 일정·공휴일이 전부** 나온다. 종류가 구분돼야 한다
- **사유·메모 마스킹 기준을 그대로 지킬 것** — 남의 연차 사유와 남의 일정 메모는
  서버가 이미 마스킹해서 내려준다. 화면에서 없는 값을 만들어 채우지 말 것
- 모달을 여는 것이 **기존 등록 패널을 방해하면 안 된다.** 날짜를 눌러 등록하던 흐름이
  살아 있어야 한다 — 어떻게 갈랐는지 결정 표에 쓸 것

## B-3 — 대시보드 "다가오는 내 일정"

사용자 요구를 그대로 옮기면 이렇다.

> 대시보드에서 자신의 일정(예: 출장)이 언제 다가오는지 보였으면 좋겠다.
> **공휴일처럼 제일 먼저 다가오는 것부터** 보여주고, 세부 내용은 **마우스를 호버해서
> 자신만** 볼 수 있게. 예를 들면 시간 같은 것.

- **본인 일정만**이다. 남의 일정은 여기 오지 않는다
- **가까운 순**으로 정렬한다. 지난 일정은 넣지 않는다
- 몇 개까지 보여줄지는 정하고 근거를 써라. 대시보드는 이미 카드가 많다
- 세부(메모 등)는 **호버로** 드러낸다. 상시 노출하지 말 것 —
  대시보드는 어깨너머로 보이는 화면이다
- 하나도 없을 때의 모습(빈 상태)을 반드시 낼 것. `EmptyState`가 있다
- 연차도 넣을지 **정하고 근거를 써라.** 요구는 "일정(EX 출장)"이라 개인 일정이 중심이지만,
  연차를 섞는 편이 나은 이유가 있으면 그렇게 하고 쓴다

## 지켜야 할 규칙

- **화살표 함수 컴포넌트 금지** — `export default function Name({ props })`
- 주석·문서는 **한국어**. 무엇이 아니라 **왜**를 쓴다. 기존 주석 문체를 따를 것
- 색·반경은 `@theme` 토큰만. `tailwind.config.js`는 **없다**
- 에러 토스트를 개별 호출부에서 띄우지 말 것 — `api/index.js` 인터셉터가 일괄 처리한다
- 쿼리 키는 기존 규칙(`['leaves', 서브리소스, ...파라미터]`)을 따를 것
- 기존 컴포넌트를 재사용할 것 (`Modal`·`Card`·`EmptyState`·`StatusBadge`·`Chip` 등)

## 테스트

**두 기능 모두 vitest 테스트를 함께 낼 것.** 이 저장소는 테스트가 명세다.

- B-2: 항목이 넘칠 때 여는 손잡이가 보이는지 / 모달에 그날 것이 전부 나오는지 /
  마스킹된 값이 새지 않는지
- B-3: **가까운 순 정렬**(가장 중요) / 지난 일정 제외 / 빈 상태 / 호버 전에는 세부가 없는지

기존 테스트 파일의 모킹 방식을 따를 것 — `vi.mock`으로 훅을 모킹하고
`createMemoryRouter` + `RouterProvider`로 감싼다 (`src/pages/MyInfoPage.test.jsx` 참고).
**앱은 2026-08-19부터 데이터 라우터다.** `BrowserRouter`로 새 테스트를 쓰지 말 것.
