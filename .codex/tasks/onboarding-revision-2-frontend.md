훅(`frontend/src/hooks/useAuth.js`)에 뮤테이션을 추가할지는 **판단해서 결정하고 근거를 적어라.**
- 이 페이지는 `RequireAuth` 안에 있고 `useCurrentUser`를 쓰게 된다(D-8). 캐시 키는 `['auth','me']`다.
- 기존 온보딩 제출(`submitOnboarding`)은 훅 없이 페이지가 직접 호출한다 — 그 패턴을 따를지,
  훅으로 올릴지 고르고 이유를 써라. 고른 쪽만 코드로 내라.
- 훅을 고쳤다면 `useAuth.js`도 전문으로 낼 것.

## 반드시 확인할 것

1. **`OnboardingPage`는 지금 `localStorage`를 직접 읽는다.** `useAuth.js` 주석이
   *"컴포넌트는 localStorage를 직접 읽지 말고 이 훅을 쓴다"*고 명시한 것과 어긋난다.
   D-8대로 `useCurrentUser()`로 바꾼다. **이유는 스타일이 아니다** — 관리자가 그사이 반려하면
   서버 상태가 바뀌는데 저장값만 보면 없는 수정권을 계속 제안한다.
2. 수정 성공 후 `localStorage` 저장 **+ react-query 캐시(`['auth','me']`) 갱신**을 함께 한다.
   저장만 하면 `useCurrentUser`의 다음 렌더가 옛 값을 쓴다.
3. 화면 문구 3갈래를 D-8 6번대로 가른다 (수정 가능 / 이미 사용 / 기능 꺼짐).
4. 에러 toast를 개별 호출부에서 띄우지 말 것 — `api/index.js` 인터셉터가 일괄 처리한다.
5. 컴포넌트는 `export default function Name({ props })` — 화살표 함수 컴포넌트 금지.
6. 스타일 토큰은 `frontend/src/index.css`의 `@theme`에 있다. **그라데이션 유틸리티는 없다**
   (2026-08-15에 전부 제거됨). 새로 만들지 말고 기존 클래스 조합을 쓸 것.
