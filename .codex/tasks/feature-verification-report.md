# 기능 검증 보고서 — 손으로 확인해야 하는 것을 추려라

이 프로젝트는 **Codex → Claude Code → 사용자** 순으로 점검한다.
너는 1단계다. 네 산출물은 사용자가 브라우저에서 직접 돌릴 **QA 문서의 입력**이 된다.

## 네가 하지 않을 것

- 코드를 고치지 마라.
- **자동 테스트가 이미 잡는 것을 QA 항목으로 올리지 마라.** 백엔드 270 · 프론트 80건이
  도메인 불변식·서비스 로직·API 계약을 덮고 있다. 그걸 사람이 또 확인하는 것은 낭비다.
- 존재하지 않는 기능을 상상해서 적지 마라. **코드에서 확인한 것만** 쓴다.

## 네가 할 것

### 1. 구현 실측

`backend/src/main/java/com/mlsoft/backend/`와 `frontend/src/`를 읽고, 기능별로:

- 어느 엔드포인트 / 어느 화면이 그 기능을 담당하는가 (파일:줄)
- 자동 테스트가 그 경로를 덮는가 (`backend/src/test/`, `frontend/src/**/*.test.jsx`를 확인)
- **덮이지 않는다면 왜인가** — 컨트롤러 계층인가, 렌더 결과인가, 브라우저 상호작용인가,
  시간에 의존하는가(스케줄러), 외부 API인가

### 2. 요구사항 대조

`docs/01-요구사항-기획.md`와 대조해 **구현이 요구사항과 어긋나는 지점**을 찾아라.
`docs/07-기능-갭분석.md`에 이미 적힌 항목은 번호만 참조하고 다시 설명하지 마라.

### 3. QA 후보 — 이게 핵심 산출물이다

**사람이 화면에서 봐야만 알 수 있는 것**만 골라라. 각 항목은 이 형식으로:

```
- [ ] 🔴/🟡 <한 줄로 무엇을 확인하는가>
  - 준비: <어떤 계정·데이터가 필요한가>
  - 절차: <1. 2. 3. 클릭 단위로>
  - 기대: <무엇이 보여야 정상인가>
  - 실패하면: <어느 파일을 의심해야 하는가>
```

🔴은 **틀리면 제품이 성립하지 않는 것**, 🟡은 확인하면 좋은 것.

### 4. 특히 이 영역들은 QA가 한 번도 안 됐다

`docs/13-QA-체크리스트.md`는 **2026-08-07에 멈춰 있다.** 그 뒤에 들어온 것들:

- **스케줄러 3잡** (매일 00:10 KST 리셋→월차→생일반차, 매년 1/1 공휴일 동기화)
  — 시간에 의존해서 사람이 기다릴 수 없다. **어떻게 확인 가능하게 만들 것인지**까지 제안하라
    (수동 트리거 엔드포인트가 있는가? 없다면 DB 날짜를 조작하는 절차인가?)
- **공휴일 API** — 외부 키가 없으면 빈 목록으로 degrade하는 설계다. 그 degrade가 화면에서
  어떻게 보이는지 확인 절차가 필요하다
- **온보딩 승인 절차** (S-1) — 자동 승인 기간 밖 입사일 → 연차 0 + 승인 대기
- **마지막 SYSTEM_ADMIN 락아웃 차단** (S-2)
- **관리자 조작 감사 로그** (S-3) — 7종 기록, append-only
- **I-7 경계값 4건** — 같은 날 오전+오후 반차 허용, primary==sub 거부, 사유 255자 경계,
  미래 입사일(KST 판정)
- **S-6** 이력 스코프가 결재자 기준(`my-approvals`)
- **F-7** 권한 변경이 재로그인 없이 반영 / **F-8** 결재 배지가 목록과 같은 기준
- **복리후생 정책 관리 화면** (신규)
- **대시보드 결재 대기 건수에 복리후생 합산** (2026-08-11, 오늘 들어감)

### 5. 테스트하면 안 되는 것

**미구현이라 "안 된다"고 보고할 필요가 없는 것**을 명시하라 — 이메일 발송(`TODO(email)` 7곳),
Google Workspace `hd` claim 검증, 설정 2키(`REMINDER_*`)의 "미동작" 배지.
QA하는 사람이 이걸 결함으로 올리면 시간이 낭비된다.

## 산출물 구조

```
## 1. 구현 실측 요약
## 2. 요구사항과 어긋나는 지점
## 3. QA 항목 (영역별)
## 4. 시간·외부 의존 때문에 확인이 어려운 것 + 확인 가능하게 만드는 방법
## 5. 테스트 대상이 아닌 것
```

분량보다 **정확성**이 중요하다. 확인하지 못한 것은 "확인 못 함"이라고 쓰라 — 추측으로 채우지 마라.
