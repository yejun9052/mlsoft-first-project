# 과제: 모바일 대응 1단계 — 기준선과 앱 껍데기

이 앱은 **사실상 데스크톱 전용**이다. 반응형 유틸리티가 전 코드베이스에 15곳뿐이고,
사이드바는 `w-[236px]` 고정, 표는 `min-w-[560px]`~`min-w-[920px]`이다.
휴대폰에서 열면 가로 스크롤로 밀려 쓸 수 없다.

모바일 대응은 화면이 15개라 한 번에 못 한다. **이번 회차는 1단계: 기준선과 껍데기**다.
뒤 회차가 이 위에 쌓을 것이므로 **여기서 정한 규칙이 나머지 전부를 좌우한다.**

## ⚠️ 출력 형식 — 수술 단위 (이 과제 전체에 적용)

`AdminMembersPage.jsx` 같은 파일은 600줄이 넘어 전문 출력이 응답 한도에 걸린다
(2026-08-20에 두 번 겪었다). **신규 파일만 전문**을 내고, **기존 파일은 아래 형식**으로 낸다.

````
### 수정 — `<파일 경로>`

#### 변경 N: <무엇을>
**찾을 것** (파일에 정확히 한 번 나와야 한다):
```
<기존 코드 3~8줄. 공백·들여쓰기까지 그대로>
```
**바꿀 것**:
```
<새 코드>
```
````

`...(생략)`·diff 기호(`+`/`-`) 금지. 두 블록은 **그대로 문자열 치환**된다.

## 이번 회차 범위 — 이것만 한다

1. **반응형 기준선 확정** (브레이크포인트·터치 타깃·안전 영역)
2. **앱 껍데기** — `Layout` + `Sidebar`를 좁은 화면에서 쓸 수 있게
3. **표를 다루는 공용 방법 1개** — 재사용 가능한 형태로
4. **대표 화면 1개**를 그 방법으로 전환해 **참조 구현**으로 삼는다

**나머지 14개 화면은 건드리지 마라.** 다음 회차다.
캘린더 그리드도 이번엔 제외한다 — 성격이 달라 따로 다뤄야 한다.

## 반드시 정하고 근거를 쓸 것 (결정 표)

1. **브레이크포인트** — Tailwind 기본(`sm/md/lg`)을 그대로 쓸지, `@theme`에 따로 둘지.
   이 앱의 진짜 분기점이 어디인지(사이드바가 안 들어가는 폭, 표가 깨지는 폭)를 근거로
2. **사이드바를 좁은 화면에서 무엇으로 바꿀지** — 서랍(drawer)인지 하단 탭인지.
   메뉴가 **역할에 따라 개수가 달라진다**(사원 6 · 팀장 8 · 총관리자 12). 하단 탭은 4~5개가 한계다.
   연차 요약과 유저 카드도 사이드바에 있다 — 그것들을 어디로 보낼지도 함께
3. **표를 좁은 화면에서 무엇으로 바꿀지** — 카드로 접을지, 가로 스크롤을 유지할지,
   열을 우선순위로 접을지. **표마다 다를 수 있다면 그 판단 기준을 쓸 것**
   (예: 열이 4개 이하면 유지, 그 이상이면 카드)
4. **대표 화면을 무엇으로 고를지** — 뒤 회차가 그대로 따라 할 수 있어야 한다.
   가장 단순한 것 말고 **가장 전형적인 것**을 골라라
5. **모달을 좁은 화면에서 어떻게 둘지** — 지금은 `max-w` 중앙 정렬이다.
   전체 화면 시트로 바꿀지, 그대로 둘지

## 지켜야 할 것 — 이 프로젝트의 규칙

- **데스크톱 모습을 바꾸지 마라.** 이번 작업은 **좁은 화면에서의 동작을 더하는 것**이다.
  넓은 화면 렌더가 달라지면 실패다 (기존 테스트 187건이 그걸 잡아 줄 것이다)
- **디자인 토큰은 `frontend/src/index.css`의 `@theme` 블록에만 있다.**
  `tailwind.config.js`는 **없다**(Tailwind v4 CSS-first). 색·반경을 리터럴로 박지 말 것.
  새 토큰이 필요하면 `@theme`에 넣고 docs/05에 무엇을 왜 넣었는지 쓸 것
- **화살표 함수 컴포넌트 금지** — `export default function Name({ props })`
- 주석·문서는 **한국어**로, 무엇이 아니라 **왜**를 쓴다. 기존 주석 문체를 따를 것
- 앱은 **데이터 라우터**다(2026-08-19). 테스트는 `createMemoryRouter` + `RouterProvider`.
  `BrowserRouter`로 쓰지 말 것
- 기존 컴포넌트를 재사용할 것 (`Card`·`TableCard`·`Table`·`Modal`·`Chip`·`StatusBadge`…).
  비슷한 것을 새로 만들지 마라
- 개별 호출부에서 에러 토스트를 띄우지 말 것 (`api/index.js` 인터셉터가 일괄 처리)

## 접근성·터치에서 반드시 지킬 것

- 누를 수 있는 것은 **최소 44×44px**. 지금 `IconButton`이 그보다 작다면 좁은 화면에서 키울 것
- 서랍/시트를 열면 **뒤 배경이 스크롤되지 않아야** 한다
- 서랍은 **Esc와 바깥 탭으로 닫힌다**. `Modal.jsx`가 이미 그 패턴을 갖고 있다 —
  **거기 주석을 반드시 읽어라.** 누른 곳과 뗀 곳이 모두 바깥일 때만 닫는 처리가 들어 있고,
  그건 2026-08-17에 실제로 겪은 결함이다
- 키보드로도 열고 닫히고, 포커스가 서랍 안에 갇혀야 한다
- 안전 영역(노치·홈 인디케이터) — 하단 고정 요소가 있으면 `env(safe-area-inset-bottom)`

## 테스트

**vitest 검증을 함께 낼 것.** 좁은 화면 동작은 눈으로만 확인하면 다음 사람이 깬다.

- 좁은 화면에서 **메뉴 버튼이 보이고**, 누르면 서랍(또는 대체물)이 열린다
- 열린 상태에서 **Esc로 닫힌다**
- 메뉴 항목을 누르면 **이동하면서 닫힌다** (열린 채로 남으면 다음 화면을 가린다)
- **역할별 메뉴 개수**가 좁은 화면에서도 그대로다 (사원에게 관리자 메뉴가 새면 안 된다)
- 넓은 화면에서는 **기존 사이드바 그대로** — 메뉴 버튼이 없다

jsdom에는 실제 뷰포트가 없다. `window.matchMedia`를 어떻게 다룰지 **정하고 근거를 쓸 것**
(`setupTests.js`에 스텁을 두는 것이 이 저장소에 맞는지 판단할 것 — 지금은 없다).
