# 11. 프로젝트 흐름

> 이 문서는 "이 시스템이 어떻게 돌아가는가"를 한 파일로 따라갈 수 있게 정리한 것이다.
> 설계 의도는 docs/01~05, 결함 목록은 docs/07·08·10에 있다. 여기는 **흐름과 현재 상태**만 다룬다.
> 최종 실측: 2026-08-06

---

## 1. 한눈에 보기

MLsoft 사내 **연차·복리후생 관리 시스템**. 이전 버전(`참고자료/MLsoft`)을 분석해 재설계한 V2.

| 구분 | 내용 |
|---|---|
| 백엔드 | Spring Boot 4 / Java 21 / JPA(Hibernate) / MySQL 8 |
| 프론트 | React 19 / Vite / Tailwind v4(CSS-first) / React Query / react-router |
| 인증 | Google OAuth2 → **JWT를 HttpOnly 쿠키로** 발급 (세션 없음, STATELESS) |
| 배포 | 루트 `Dockerfile` 3단계 멀티스테이지 → **단일 컨테이너·단일 포트 8080** |
| 규모 | 엔드포인트 **49개**(컨트롤러 11) · 엔티티 **14개**(+ENUM 4) · 화면 **14개** |
| 테스트 | 백엔드 103 (서비스 13개 클래스 + `UserTest` 도메인 불변식) · 프론트 30 |

**핵심 설계 결정 3가지** — 이걸 모르면 코드가 이상하게 보인다.

1. **JWT는 상태를 못 담는다** → 발급 후 퇴직·권한 변경을 반영할 수 없으므로,
   `OnboardingCheckInterceptor`가 `/api/**` 전역에서 **매 요청 DB를 조회**해 다시 검사한다.
2. **연차는 신청 시점에 선차감**한다 → 승인 시가 아니라 `PENDING`이 될 때 `use_days`가 깎인다.
   반려·취소는 "복구" 동작이다.
3. **토큰 이름은 고정, 값만 교체** → 디자인 토큰(`navy-*`/`accent-*`/`ink-*`)은 이름을 유지해서
   페이지에 흩어진 유틸리티 클래스가 팔레트 변경을 자동으로 따라오게 한다.

## 2. 요청 하나가 흐르는 길

### 2-1. 로그인 (최초 1회)

```
브라우저
  │ "Google 계정으로 로그인" 클릭
  ▼
GET /oauth2/authorization/google        ← Spring Security가 처리 (컨트롤러 없음)
  │
  ▼ Google 인증 후 콜백
CustomOAuth2UserService
  │ ① 이메일 추출
  │ ② 도메인 검증 (app.allowed-domain)   ⚠️ 비어 있으면 검증 안 함 = O-1 fail-open
  │ ③ 없는 계정이면 자동 가입
  │    └ ADMIN_EMAILS에 있으면 SYSTEM_ADMIN 부여 (최초 가입 시에만!)
  ▼
OAuth2SuccessHandler
  │ JWT 생성 → HttpOnly 쿠키로 심음 (COOKIE_SECURE 운영 필수)
  ▼
프론트 /oauth/callback (OAuthCallbackPage)
  │ GET /api/auth/me 로 내 정보 조회 → localStorage.userInfo 저장
  ▼
hire_date 있음? ──아니오──▶ /onboarding (생년월일·입사일 입력)
  │ 예
  ▼
/dashboard
```

### 2-2. 로그인 이후 모든 API 요청

```
프론트 페이지
  │ 예: DashboardPage가 useLeaveSummary() 호출
  ▼
hooks/useLeaves.js          React Query 래퍼 (쿼리 키 = ['leaves', 서브리소스, ...파라미터])
  ▼
api/leaves.js               엔드포인트 1:1 함수, res.data.data 언랩
  ▼
api/index.js                axios 인스턴스 (withCredentials: true)
  │                         └ 응답 인터셉터: 401 → localStorage 정리 + 로그인 리다이렉트
  │                                          그 외 에러 → 서버 메시지를 toast로 일괄 표출
  ▼ (dev: vite 프록시 5173 → 8080 / prod: 같은 오리진)
─────────────────────── 백엔드 ───────────────────────
JwtFilter                   쿠키에서 JWT 읽어 AuthUser principal을 SecurityContext에 세팅
  ▼
SecurityFilterChain         경로별 인증 요구
  ▼
OnboardingCheckInterceptor  ★ /api/** 전역 가드 — 매 요청 DB 조회
  │ ① 퇴직자(is_active=false)      → 로그아웃 외 전 경로 차단
  │ ② DB role ≠ 토큰 role          → SecurityContext 권한을 DB 기준으로 재구성
  │ ③ 온보딩 미완료(hire_date null) → /api/auth/* 외 403
  ▼
Controller                  @PreAuthorize는 역할 게이트 전용
  │                         본인 식별은 @AuthenticationPrincipal AuthUser에서만
  ▼
Service                     ★ 소유권·승인자 식별 검증은 여기 책임
  │                         실패는 BusinessException(ErrorCode)
  ▼
Repository → MySQL
  ▲
  │ 예외 발생 시
GlobalExceptionHandler      ErrorCode → HTTP status + 메시지로 일괄 변환
  ▼
CommonResponse<T>           모든 응답이 { success, message, data } 로 래핑
```

**왜 인터셉터가 필요한가** — JWT는 발급 시점의 스냅샷이다. 관리자가 누군가를 팀장으로 승격하거나
퇴직 처리해도 그 사람의 쿠키 안 토큰은 그대로다. 그래서 매 요청 DB로 재확인한다.
대가는 요청당 유저 조회 1회.

## 3. 연차 잔액이 변하는 길 ★ 가장 중요

### 3-1. 기본 식

```
잔여(remaining) = base_days + bonus_days − use_days
```

`use_days`는 **확정 사용 + 대기 중 선차감**을 모두 포함한다.
`pending_days`(PENDING 신청 일수 합)는 `use_days` 안에 이미 들어 있다.

### 3-2. 상태 전이

```
                  ┌──────────────────────────────────────────┐
                  │  신청 (POST /api/leaves)                  │
                  │  ★ 이 시점에 use_days 선차감              │
                  │  잔여 부족 + 당겨쓰기 ON이면              │
                  │  부족분이 advance_days에 잡힌다            │
                  │  → LeaveRequest.advanceUsedDays 는 감사용 │
                  └──────────────┬───────────────────────────┘
                                 ▼
                            ┌─────────┐
                            │ PENDING │
                            └────┬────┘
              승인 ┌─────────────┼─────────────┐ 반려
                   ▼             │             ▼
             ┌──────────┐        │       ┌──────────┐
             │ APPROVED │        │       │ REJECTED │
             └────┬─────┘        │       └──────────┘
                  │              │        use_days 복구
       본인 취소 신청             │        → advance_days 는
                  │           본인 취소    재계산으로 따라옴
     ┌────────────┴───────┐      ▼
     │ 미래 날짜만 포함    │  ┌───────────┐
     │ → 즉시 CANCELLED   │  │ CANCELLED │
     │                    │  └───────────┘
     │ 과거 포함(소급)     │
     │ → CANCEL_PENDING   │
     └────────┬───────────┘
              ▼
      ┌────────────────┐
      │ CANCEL_PENDING │ ← 결재자가 승인/거부
      └────────────────┘
         승인 → CANCELLED (복구)
         거부 → APPROVED 로 되돌림
```

**`advance_days`는 파생값이다** — 되돌리는 게 아니라 매번 다시 계산한다 (2026-08-06, 리뷰 I-1).

```
advance_days = max(0, use_days − base_days − bonus_days)
```

`User.syncAdvanceDays()` **하나만** 이 필드에 쓰고, 잔액 3필드를 바꾸는 도메인 메서드 6개가
(`deductLeave`·`restoreLeave`·`addBonusDays`·`updateBaseDays`·`addMonthlyLeave`·`resetAnnualLeave`)
마지막에 이걸 호출한다. **예외 없다.**

왜 이렇게 됐나 — 예전에는 신청별 `advanceUsedDays` 스냅샷을 빼서 복구했는데, 그러면
**취소 순서에 따라 결과가 달라졌다.** A(8일)·B(5일)를 신청하고 A를 먼저 취소하면 B는 잔여로
충당되는데도 당겨쓰기 3일이 남아, 다음 기산일에 쓰지 않은 3일이 삭감됐다.
보너스 가산·관리자 연차 변경·월차 적립도 같은 이유로 정산이 누락됐다 (I-1·I-2·I-8이 한 원인).

`LeaveRequest.advanceUsedDays`는 **감사 기록으로만** 남는다 — 복구 계산에는 쓰이지 않는다.

`RequestStatus`(PENDING/APPROVED/REJECTED/CANCELLED/CANCEL_PENDING)는 연차·복리후생이 공유한다.
취소 승인/거부의 **세부 결과는 status가 아니라** `action_history`의 `RequestAction`으로 기록한다.

### 3-3. 동시성

`User`에 `@Version` 낙관적 락. 두 창에서 동시 신청해도 초과 차감되지 않는다.
상태 전이는 전부 도메인 메서드(`deductLeave` / `restoreLeave` / `resetAnnualLeave`) 안에 있고
**Setter는 없다.**

### 3-4. 규칙

- 연차 일수는 **`BigDecimal`만** (double 금지, DB는 `DECIMAL(4,1)`)
- 비교는 `compareTo`, **`==` 금지**

## 5. 데이터 흐름 규칙 (프론트)

```
api/*.js        엔드포인트 1:1 함수. res.data.data 언랩. 여기서 toast 띄우지 말 것
   ▼
hooks/use*.js   React Query 래퍼. 쿼리 키 = ['leaves', 서브리소스, ...파라미터]
   ▼            → 접두사로 일괄 invalidate 가능
페이지
```

- **에러 toast는 `api/index.js` 인터셉터가 일괄 처리** — 개별 호출부에서 중복으로 띄우지 말 것
- 권한 가드는 `RequireAuth`(라우트 레벨)로 선차단. **useEffect 내 리다이렉트 금지**(깜박임·우회)
- React 컴포넌트는 `export default function Name({ props })` — 화살표 함수 컴포넌트 금지

## 6. 스타일 (Tailwind v4 CSS-first)

**`tailwind.config.js`는 없다.** 토큰은 `frontend/src/index.css`의 `@theme`, 커스텀 유틸리티는 `@utility`.
값의 단일 출처는 `index.css`이고 docs/05가 그걸 문서화한다.

핵심 규칙 2개:
- **그라데이션은 2곳만** — 브랜드 마크, 대시보드 히어로 숫자. 나머지는 전부 단색
  (한때 13곳이었는데 서로 강조를 상쇄했다)
- **`accent-gradient-action`에는 반드시 `text-navy-app`** — 흰 글자는 시안 구간에서 1.81:1

## 7. 로컬 실행

```powershell
# 백엔드 (MySQL96 서비스가 Running이어야 함)
$env:SPRING_PROFILES_ACTIVE = 'local'; .\gradlew.bat bootRun   # 8080

# 프론트
npm run dev                                                     # 5173 (/api·/oauth2를 8080으로 프록시)
```

`/dev` 슬래시 커맨드가 둘 다 띄운다. **서버를 도구의 `run_in_background`로 띄우면 안 된다** —
세션 하네스가 백그라운드 작업을 정리할 때 서버까지 죽는다. `Start-Process`로 분리할 것.

| 파일 | 커밋 | 내용 |
|---|---|---|
| `application.yml` | ✅ | 공통 설정, 시크릿은 `${ENV}` 참조만 |
| `application-local.yml` | ❌ gitignored | 로컬 실제 시크릿 |
| `application-example.yml` | ✅ | 템플릿 |

`ADMIN_EMAILS`는 **최초 자동 가입 시에만** SYSTEM_ADMIN을 부여한다.
이미 가입된 계정 승격은 `UPDATE users SET role='SYSTEM_ADMIN'` + **재로그인**이 함께 필요하다.
