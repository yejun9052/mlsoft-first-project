> 기준 해상도 1480×864 데스크탑. 마크업은 레퍼런스일 뿐, React + Tailwind로 재구현한다.

#### 그라데이션 — **면은 0곳이다** (2026-08-15)

한때 Primary 버튼·세그먼티드·탭 밑줄·게이지·토글·워드마크까지 **13곳**이 그라데이션이었다.
면이 너무 많아 서로 강조를 상쇄해 **2곳**(브랜드 마크·히어로 숫자)으로 줄였고,
같은 지적이 다시 나와 **그 둘도 단색으로 내렸다.**

| 없앤 유틸리티 | 대체 | 대비 |
|---|---|---|
| ~~`accent-gradient-action`~~ | 브랜드 마크 → `bg-accent` + **`text-navy-app`** | 5.31:1 |
| ~~`accent-gradient-text`~~ | 히어로 숫자 → `text-accent-light` | 8.47:1 (카드 위) |

**두 유틸리티는 이름째로 삭제했다.** 정의가 남아 있으면 "여기 하나쯤은" 하고 다시 쓰인다.
새로 그라데이션 면을 만들지 말 것 — 강조는 색상 대비와 크기로 만든다.

**대비는 오히려 좋아졌다.** 그라데이션은 세 정지점 중 가장 어두운 구간이 5.31:1이라 거기에 맞춰
글자를 뒤집어야 했지만, 단색은 그 하한이 곧 실제 값이다. 히어로 숫자는 텍스트 클리핑을 걷어내
5.31 → **8.47:1**이 됐다. 그라데이션일 때는 시안 구간이 밝아 눈에 띄었을 뿐 대비가 균일하지 않았다.

남은 그라데이션은 **면이 아닌 것 둘**뿐이다:
- `glass-edge` — 카드 상단 1px 하이라이트. 배경과 카드가 둘 다 어두워 경계를 만드는 **기능**이다
- `ambient-glow` — 페이지 배경 광원. 알파를 `0.22/0.14` → **`0.06/0.04`**로 낮췄다.
  지우지 않은 이유는 넓은 화면에서 바닥이 죽은 검정으로 보이는 것을 막기 위함이다

#### 단색 강조
| 용도 | 값 | 대비 |
|---|---|---|
| Primary 버튼, 세그먼티드 활성, 오늘 표시, 게이지 채움, 토글 ON, **브랜드 마크** | `bg-accent` + **`text-navy-app`** | 5.31:1 |
| **히어로 숫자** (잔여 연차 52px) | `text-accent-light` | 8.47:1 |
| 사이드바 활성 바, 탭 밑줄 | `bg-accent-cyan` | 장식(글자 없음) |
| 워드마크("연차ON") | `text-ink-hi` 단색 | 브랜드 마크와의 강조 중복 회피 |
| **승인 아이콘 타일** (IconButton `tone="confirm"`) | `bg-ok` + **`text-navy-app`** | 12.4:1 |
| **반려 아이콘 타일** (IconButton `tone="deny"`) | `bg-danger` + **`text-navy-app`** | 7.45:1 |

**밝은 면 위에 흰 글자·글리프를 쓰지 말 것.** `accent #3b7dff` + 흰 글자는 3.77:1,
`ok #2ee6a8` 위 흰 글리프는 1.6:1, `danger #fb7185` 위는 2.7:1이다 —
아이콘의 최소 기준(비텍스트 대비 3:1)에도 못 미친다. 전부 `text-navy-app`으로 뒤집는다.

#### 보더 알파 위계
| 알파 | 용도 |
|---|---|
| `0.15` | 조작 컨트롤 (input, textarea, secondary 버튼, toggle 비활성) |
| `0.12` | 카드·모달 외곽선, 섹션 구분선, 테이블 헤더 하단, 비선택 chip |
| `0.10` | 카드 내부 약한 구분선 (`divide-*`, 테이블 데이터 행) |

테이블은 **헤더(0.12) > 데이터 행(0.10)** 순서를 지킨다 — 행이 더 진하면 카드 외곽보다 내부
그리드가 강해져 위계가 뒤집힌다.

**배지 틴트 배경**: 승인 `rgba(46,230,168,.12)` / 대기 `rgba(251,191,36,.13)` / 반려 `rgba(251,113,133,.13)` / 시안 `rgba(34,211,238,.12)`
— 글래스 표면 위에서는 틴트만으로 경계가 흐려지므로 **같은 색 `ring-1 ring-inset`을 함께 두른다.**

### 연차 히트맵 (2026-08-20)

깃 잔디 그래프 형태로 연차 사용을 보여준다 — **내 정보**(내 사용 일수)와
**팀 관리**(그 날짜에 쉬는 인원 수). 토큰은 `index.css`의 `@theme`에 있다.

| 토큰 | 뜻 |
|---|---|
| `--color-heatmap-empty` | 사용 없는 **평일** |
| `--color-heatmap-rest` | **주말·공휴일** — 근무일이 아니라 "0일"과 구분해야 한다 |
| `--color-heatmap-1` ~ `-4` | 사용량 4단계. 개인은 `0.5 / 1.0 / 1.5 / 2.0일 이상`, 팀은 `1 / 2 / 3 / 4명 이상` |
| `--radius-heatmap` | 칸 모서리 2px |

**단계를 값 기준으로 고정한 이유** — 백분위로 나누면 같은 "하루 사용"이 연도마다
다른 색이 되어 해를 넘겨 비교할 수 없다.

**개인 값은 `BigDecimal`이다.** 반차 단가가 0.5일이라 하루가 0.5·1.0·1.5가 될 수 있다.
건수를 세면 반차와 종일이 구분되지 않는다.

**팀 히트맵은 인원 수만 받는다.** 서버 응답에 이름·사유·신청 ID가 아예 없어
렌더링 실수로 개인정보가 샐 경로 자체가 없다 (연차 사유 마스킹과 같은 기준).

**승인 완료 건만 반영한다** — 대기·반려는 그리지 않는다.

### 글래스 서피스 규칙
| 유틸리티 | 용도 | 구성 |
|---|---|---|
| `glass` | 카드·패널 기본 | `navy-card` 86% + `blur(20px) saturate(140%)` |
| `glass-strong` | 모달·사이드바·툴팁 (뒤를 가려야 하는 면) | `navy-card` 91% + `blur(28px) saturate(150%)` |
| `glass-edge` | 유리 모서리 1px 하이라이트 (`::before`) | 투명→페리윙클(.35)→화이트(.14)→투명 가로 그라데이션 |
| `ambient-glow` | 앱 셸/풀스크린 바닥 광원 | 코발트(좌상) + 시안(우하) radial, `fixed`, `z-index:-10` |

**주의**: `ambient-glow`는 `z-index:-10` 고정 레이어라, 그 위에 불투명 배경을 깔면 글로우가 가려진다.
→ 앱 배경은 `body`의 `bg-navy-app` 하나로만 칠하고 셸/콘텐츠는 투명하게 둔다 (`Layout.jsx`).

더 심한 증상이 있었다. 그 위험은 사라졌지만 형제 구조를 유지할 이유는 남아 있다.)

### 간격·라디우스·섀도우
- 콘텐츠 패딩 26×30px, 카드 패딩 18~26px, 카드 gap 14~16px
- radius: 윈도우 20 / 카드 18 / 버튼·입력 11 / 배지 999(pill)
- 섀도우: 카드 `0 24px 64px -16px rgba(0,2,8,.95)` + `inset 0 0 0 1px rgba(147,180,255,.04)`,
  Primary 버튼 `0 8px 24px -8px rgba(59,125,255,.7)`,
  글로우 `0 0 32px -6px rgba(34,211,238,.42)` (hover lift·활성 밑줄에 사용)
- 카드 경계는 **border(0.12) + `glass-edge` 상단 하이라이트 + 섀도우 inset 링** 세 겹이 겹친다.
  inset 링을 가장 약하게(0.04) 두는 이유 — 셋이 같은 세기면 테두리만 도드라진다.
- **사이드바 236px 고정**, 콘텐츠 flex:1

## 화면 구조 (5개)

- **내 연차 요약 패널** — 잔여 연차(21px 시안) + 소진 게이지 + 사용·대기 일수.
  일반 직원은 메뉴가 6개뿐이라 아래가 비어 보이던 공간을 채운다. `mt-auto`로 유저 카드 바로 위에 붙인다.
  `useLeaveSummary`는 대시보드와 쿼리 키가 같아 **캐시를 공유하므로 추가 요청이 없다.**

## Tailwind 설정 — v4 CSS-first

**`tailwind.config.js`는 없다.** Tailwind v4의 CSS-first 방식이라 토큰은 전부
`frontend/src/index.css`의 `@theme` 블록에, 커스텀 유틸리티는 `@utility` 블록에 있다.
(아래는 형태만 보여주는 발췌 — 실제 값의 단일 출처는 `index.css`다.)

```css
@theme {
```

## 구현 주의사항

**네이티브 `<select>`의 옵션 목록은 컴포넌트 밖에서 그려진다.** 브라우저가 페이지 밖 팝업으로
띄우므로 `<select>`에 준 클래스(반투명 배경·`text-ink-hi`)가 목록에는 닿지 않는다.
`[color-scheme:dark]`도 **패널 배경만** 어둡게 할 뿐 글자색은 정해 주지 않는다 —
그것만 믿었다가 어두운 패널 위에 어두운 글자가 얹혀 선택지가 안 보였다(2026-08-15 부서 변경 모달).

색은 `index.css`의 전역 `option` 규칙이 담당한다. **`option`에는 불투명 색을 준다** —
반투명 값은 팝업에 합성할 바탕이 없어 의도대로 나오지 않는다.

| 대상 | 값 | 대비 |
|---|---|---|
| `option` | `bg: navy-card` / `color: ink-hi` | 14:1 |
| `option:disabled` (플레이스홀더) | `color: ink-faint` | 4.72:1 — 흐리되 읽을 수는 있어야 한다 |

컴포넌트 쪽에서 옵션 색을 다시 주려 하지 말 것.

**Tailwind v4에는 `button { cursor: pointer }`가 없다.** v3 preflight에 있던 그 한 줄이
v4에서 빠져 브라우저 기본값(화살표)이 그대로 적용된다. 글자가 있는 버튼은 생김새로 알아보지만
아이콘만 있는 버튼은 커서가 유일한 단서라 거기서 티가 났다(2026-08-16).
`index.css`가 `button:not(:disabled)`로 되살린다 — **`:not(:disabled)`를 떼지 말 것.**
이 규칙은 레이어 밖이라 유틸리티보다 세서, 조건이 없으면 `disabled:cursor-not-allowed`를 덮는다.

**아이콘 버튼은 쉬는 상태에도 테두리를 준다** (`IconButton`). hover에서만 배경이 나타나면
마우스를 올려보기 전에는 버튼인지 장식인지 알 수 없다. tone은 두 갈래로 쓴다 —
윤곽선 계열(`muted`/`danger`/`accent`)은 목록 행의 보조 동작, 채워진 타일(`confirm`/`deny`)은
**되돌리기 어려운 이지선다 전용**이다. 남발하면 "무거운 결정"이라는 신호가 죽는다.
연차 정책의 인라인 편집이 그 경계다 — 저장은 `confirm`(초록 타일)이지만 취소는 `danger`(빨간 윤곽선)다.
편집을 접는 것은 파괴적이지 않다.

## 모바일 기준선

- 앱 셸은 Tailwind 기본 `lg`(1024px) 미만에서 사이드바를 왼쪽 서랍으로 바꾼다.
  236px 사이드바와 콘텐츠 좌우 패딩 60px를 제외하면 768px 화면에는 472px만 남아 가장 작은
  560px 업무 표도 들어가지 않기 때문이다.
- 표는 기본 `md`(768px) 미만에서 `ResponsiveTable`의 카드 슬롯으로 전환한다.
  열이 4개 이하이고 셀이 짧은 비교표는 표를 유지할 수 있다. 5개 이상이거나 긴 설명·복합 셀·행 액션이
  있으면 카드로 바꾸며, 핵심 식별값과 상태를 카드 헤더에 두고 나머지는 라벨-값 쌍으로 배치한다.
- 눌리는 요소는 `lg` 미만에서 최소 44×44px다. 데스크톱의 기존 밀도를 보존하기 위해 `lg` 이상에서는
  원래 컴포넌트 크기로 돌아간다.
- 고정 셸과 전체 화면 시트는 `100dvh`를 사용한다. 노치와 홈 인디케이터는
  `safe-area-top`, `safe-area-bottom` 유틸리티로 피한다.
- 모바일 탐색은 하단 탭이 아니라 `MobileDrawer`다. 역할별 메뉴가 6·8·12개이고 연차 요약과 유저 카드도
  탐색 컨텍스트이므로 모두 서랍 안에 유지한다. 서랍은 배경 스크롤 잠금, Esc·바깥 탭 닫기,
  포커스 트랩과 닫힌 뒤 트리거 포커스 복귀를 지켜야 한다.
- 공용 `Modal`은 `sm` 미만에서 전체 화면 시트, 그 이상에서 기존 중앙 `max-w` 모달이다.
  모바일 푸터에는 홈 인디케이터 안전 영역을 더한다.
- `@theme`에는 색·반경·그림자 토큰만 둔다. 이번 기준선은 Tailwind 기본 breakpoint를 그대로 사용하므로
  별도의 화면 폭 토큰을 추가하지 않는다.
