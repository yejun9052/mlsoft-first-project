## 2. ERD — 개발자용 (6·7장)

**네이티브 도형만.** 엔티티 = 사각형 하나(상단 진한 띠에 테이블명, 아래에 컬럼 줄). 관계 = 직교 커넥터 + 양 끝에 `1` / `N` 라벨, 선 중간이나 N쪽에 FK 컬럼명. 까마귀발 대신 `1`·`N` 글자로 표기해도 된다(PowerPoint 커넥터로 까마귀발을 그릴 수 없으니). PK는 `id PK`, FK는 `xxx_id FK → 테이블` 식으로 컬럼 줄에 표시. 글자 10~11pt, 엔티티 폭 2.1~2.4in. 겹침 금지, 커넥터가 다른 엔티티를 관통하지 않게 배치.

정보 원천은 `db/schema.sql`이다. 아래는 오케스트레이터가 뽑아 둔 것 — **그대로 쓰되 schema.sql과 한 번 대조**한다.

### FK 27개 (자식.컬럼 → 부모)
```
users.department_id → department
department.leader_id → users            (department.parent_id → department 자기참조)
employment_periods.user_id → users
leave_requests.user_id / primary_approver_id / sub_approver_id → users
leave_dates.leave_requests_id → leave_requests
leave_action_history.leave_requests_id → leave_requests · user_id / actor_id → users
leave_reset_history.user_id → users
welfare_requests.user_id / primary_approver_id / sub_approver_id → users · policy_id → welfare_policies
welfare_action_history.welfare_request_id → welfare_requests · user_id / actor_id → users
email_history.user_id / from_id → users
email_templates.updated_by → users
leave_reminder_dispatch.user_id → users · email_history_id → email_history   (UNIQUE user_id, cycle, period_key)
schedule_entries.user_id → users
schedule_dates.schedule_entry_id → schedule_entries
admin_audit_log.actor_id(nullable) / target_user_id → users
```
FK 없는 독립 테이블: holidays · leave_policy · leave_policy_config · mail_credentials · holiday_api_credentials.

### 6장 ERD 1 — 엔티티 10개와 보여 줄 컬럼 (줄 수를 이 정도로 유지)
- **users**: id PK · email · name · role · department_id FK→department · hire_date · last_reset_date · base_days · bonus_days · use_days · advance_days · onboarding_status · is_active · retired_at · purged_at · version
- **department**: id PK · name · parent_id FK→department · leader_id FK→users · system_default · active
- **employment_periods**: id PK · user_id FK · seq · hire_date · retired_at
- **leave_requests**: id PK · user_id FK · primary_approver_id FK→users · sub_approver_id FK→users · status · leave_type · days · request_reason · cancel_reason · advance_used_days
- **leave_dates**: leave_requests_id FK · day  (두 컬럼이 복합 PK)
- **leave_action_history**: id PK · leave_requests_id FK · user_id FK · actor_id FK · action · comment
- **leave_reset_history**: id PK · user_id FK · reset_date · prev_base_days · new_base_days · prev_use_days · carried_bonus_days · expired_days · advance_settled
- **welfare_policies**: id PK · category · target · default_days · default_evidence · active
- **welfare_requests**: id PK · user_id FK · policy_id FK→welfare_policies · primary_approver_id FK · sub_approver_id FK · status · category · target · add_days · reason
- **welfare_action_history**: id PK · welfare_request_id FK · user_id FK · actor_id FK · action · comment

배치 제안: users를 가운데 위쪽, 왼쪽에 department·employment_periods, 오른쪽 위에 welfare_policies→welfare_requests→welfare_action_history, 아래에 leave_requests→leave_dates·leave_action_history, leave_reset_history. 승인자 FK 2개는 선 하나에 "primary_approver_id · sub_approver_id"로 합쳐 표기해도 된다.

### 7장 ERD 2 — 엔티티 11개 + users 참조
- **users** (참조용 작은 상자: id PK · name · role 만)
- **email_history**: id PK · user_id FK · from_id FK→users · email_type · status · retry_count · sending_at · sent_at · error_message · title
- **leave_reminder_dispatch**: id PK · user_id FK · email_history_id FK · cycle · period_key · reference_date · next_reset_date · remaining_days_snapshot · result
- **email_templates**: id PK · template_key · subject_template · body_template · version · updated_by FK→users
- **mail_credentials**: id PK · provider · username · encrypted_secret · active
- **schedule_entries**: id PK · user_id FK · schedule_type · memo
- **schedule_dates**: schedule_entry_id FK · day (복합 PK)
- **holidays**: id PK · date · name · year
- **admin_audit_log**: id PK · actor_id FK→users (nullable) · target_user_id FK→users · action · target_label · before_value · after_value
- **leave_policy**: id PK · years_of_service · annual_leave_days · active
- **leave_policy_config**: id PK · name · value
- **holiday_api_credentials**: id PK · provider · encrypted_api_key · active

각주 예: "상태·종류 컬럼은 MySQL ENUM. 연차 일수는 DECIMAL(4,1). 파기 시 행을 지우지 않고 users의 이름·이메일과 사유 본문만 익명화."

## 3. 루프 — 흐름도 4장

원칙: **막히거나 반려된 결과가 막다른 상자로 끝나지 않는다.** 그 상자에서 **"수정 후 다시 신청"** 같은 라벨이 붙은 화살표가 신청 단계로 되돌아간다. 되돌아가는 선은 다이어그램 바깥(왼쪽·아래)으로 직교 경로를 잡아 다른 상자를 가로지르지 않게. `arrow()`는 직교 선분만 받는다.

- **8장 신청·결재**: 검증 실패 → "사유 확인 · 날짜/내용 수정" → **신청으로 되돌아감**. 반려 → 잔액 복구 → "반려 사유 확인 후 수정" → **신청으로 되돌아감**. 승인 → 끝(연차 사용). 각주에 "복리후생 신청도 같은 결재 흐름 — 승인 시 보너스 연차로 가산"과 메일 수신자(신청: 신청자+승인자 2명 / 결과: +재직 총관리자 전원)를 넣는다.
- **9장 취소**: 즉시 취소·취소 승인 → 잔액 복구 → "필요하면 다시 신청" (8장으로 이어진다는 표시). 취소 거부 → 승인 상태 유지 → **"다시 취소 요청 가능" 루프**로 취소 요청 상자로 되돌아감. 규칙(지난 날짜 포함 시에만 결재)은 유지.
- **10장 잔액 계산**: 신청 제한(당겨쓰기 불가/상한 초과) → "날짜를 줄여 다시 신청" **루프**. 예약 한도 초과도 같은 루프.
- **11장 온보딩**: 반려 → "입사일 재입력" → **판정으로 되돌아감**. "대기 중 1회 수정 가능"도 같은 되돌림 화살표로 표현(현재는 문장으로만 있음).

## 4. 흡수하는 내용 (삭제한 장의 알맹이)

- 복리후생 흐름 → 8장 각주 한 줄.
- 이메일 경로 → 3장(외부 API) 각주: "메일은 업무 저장과 함께 큐에 적재 → 15분마다 재시도(총 3회) → 실패 건은 관리자 수동 재발송".
- 권한 → 4장(서버 내부) 각주: "매 요청 서버가 재직·역할·온보딩 상태를 재확인 · 본인 결재 금지(총관리자 예외) · 마지막 총관리자 강등·본인 퇴직 처리 금지".
- 핵심 테이블 표 → ERD 컬럼으로 대체.

## 5. 제작 조건

- 스크립트 안의 `validate_deck()`를 새 구성에 맞게 고친다(장수 15, 네이티브 표가 있는 장 = 3·4·14, 흐름도 장 = 8~11). 검증이 통과해야 한다.
- 글자 최소 10pt(ERD 컬럼 줄만 10pt 허용, 나머지 11pt 이상). 겹침·잘림·페이지 밖 도형 없음.
- **PNG 검수**: `Get-Process POWERPNT`로 PowerPoint가 떠 있으면 COM을 쓰지 말 것(사용자 창을 닫아 버린다). 그때는 python-pptx로 도형 경계·겹침을 계산해 검사하고 보고에 "PNG는 오케스트레이터가 확인"이라고 적는다. 떠 있지 않으면 1차 때처럼 COM으로 전 장 PNG를 내보내 눈으로 본다.
- `docs/발표자료/README.md`의 소개 장표 줄을 새 구성(15장)으로 고친다.
- 코드 식별자는 ERD·기술 스택에서만 쓴다(개발자 대상이라 허용). 흐름도는 여전히 한국어 설명.
- git commit/push 금지. 변경 파일 목록만 보고.
