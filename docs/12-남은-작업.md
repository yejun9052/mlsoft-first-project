## ① 배포 전 필수 — ✅ **전부 완료 (2026-08-07)**

> 4건 모두 닫혔다. 아래는 무엇을 어떻게 막았는지의 기록이다.
> **남은 것은 배포 시점의 확인 2가지뿐** — 이미지에 시크릿이 없는지, 운영 DB에 backfill을 돌렸는지.

- [x] ~~**O-4 🔴 시크릿이 운영 이미지에 포함된다**~~ — **2026-08-07 해소**
  `.dockerignore`에 시크릿 블록 추가 (명시 경로 + `**` 패턴 + `.env*`).
  유출 경로는 재현으로 확인했다 — `gradlew processResources` 후
  `backend/build/resources/main/`에 `application-local.yml`이 그대로 나오고,
  `Dockerfile:20 COPY backend/ ./` → `bootJar` → 최종 이미지로 이어진다.
  ⚠️ **docker 데몬이 없어 이미지 빌드로 최종 확인은 못 했다.** 첫 배포 시
  `docker run --rm --entrypoint sh <이미지> -c "unzip -l /app/app.jar | grep local"`로 한 번 확인할 것.
- [x] ~~**O-2 🔴 운영이 `ddl-auto: update`를 상속**~~ — **2026-08-07 해소**
  `application-prod.yml` 신설 + `ddl-auto: validate` 고정, 운영 로그 레벨도 debug → info로 낮췄다
  (base의 debug가 요청 파라미터·엔티티 값을 그대로 찍는다).
  **`validate`만 걸면 빈 DB에 첫 배포가 실패**하므로 스키마 부트스트랩을 함께 만들었다 —
  `db/schema.sql`(로컬 DB 덤프, 13테이블)을 compose가 mysql의 `/docker-entrypoint-initdb.d/`에
  마운트한다. MySQL은 데이터 볼륨이 비어 있을 때만 실행하므로 재기동해도 덮어쓰지 않는다.
  검증: 빈 DB를 만들어 `schema.sql`만 적용 → prod 프로필로 기동 → **`Started` 성공**.
  ⚠️ **엔티티를 바꾸면 `db/schema.sql`도 함께 갱신**해야 한다. 안 하면 배포가 거기서 멈춘다
  (그게 이 설정의 목적이다 — 조용한 ALTER보다 낫다). Flyway 전환은 docs/08 Y-6 / 아래 ⑧.
- [x] ~~**O-1 🔴 도메인 검증 fail-open**~~ — **2026-08-07 해소**
  `AllowedDomainCheck` 신설 — `local`·`test`가 아닌 프로필에서 `app.allowed-domain`이 비면 기동 거부
  (`CookieSecurityCheck`와 같은 패턴). `@`로 시작하거나 공백이 섞인 형식 오류도 함께 막는다.
  `.env.prod.example`의 `ALLOWED_DOMAIN=`을 `mlsoft.com`으로 채웠다 — **빈 값을 그대로 복사하는 게
  실제 사고 경로**였다. 환경변수가 "빈 값으로 설정된" 상태면 `${ALLOWED_DOMAIN:mlsoft.com}`의
  기본값이 적용되지 않는다.
  검증: 빈 값 주입 → `IllegalStateException` + `bootRun FAILED` + 8080 미리스닝 확인.
- [x] ~~**O-3 🔴 기존 데이터 backfill 2건**~~ — **2026-08-07 로컬 DB 적용 완료**
  `db/backfill-2026-08-07-O3.sql`로 남겼다(멱등, 여러 번 실행 가능).
  로컬 결과 — `department` **1행 변경**(`미배정`이 `active=0`으로 실제 깨져 있었다),
  `users.advance_days`는 **0행 변경**(이미 정합).
  ⬜ **홈서버 운영 DB에는 아직 적용 안 함** — 배포 확인 시 실행할 것.
