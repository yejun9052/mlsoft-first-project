## 시작 전

1. 테스트용 계정으로 진행한다. 운영 계정·운영 DB에서 실행하지 않는다.
2. **관리자 1개 + 온보딩 대기 사용자 2개 + 즉시 통과 확인용 신규 사용자 1개**를 준비한다. I-3에서 I-1 계정을 승인하면 완료 상태가 되므로 I-4에는 별도의 대기 계정을 쓴다.
   - 데모 계정 8명은 Google OAuth 로그인이 되지 않으므로 사용하지 않는다.
   - 관리자 계정을 대기 상태로 만들지 않는다. 대기 계정은 구성원 관리 API에 접근할 수 없어 I-3을 수행할 수 없다.
   - 계정 준비가 안 되면 SQL을 운영 DB에 임의 실행하지 말고 `UNKNOWN — 테스트 계정 준비 불가`로 남긴다. 필요하면 Codex/Claude에게 **로컬 테스트 DB용** 계정 reset을 요청한다.
3. 앱 주소 `http://localhost:5173`과 API `http://localhost:8080`이 모두 열리고 응답하는지 확인한다. 서버가 없으면 Claude의 `/dev` 명령으로 먼저 실행한다. Codex는 이 프로젝트 규칙상 서버를 기동하지 않는다.
4. 관리자 정책에서 `onboarding_auto_approve_days`의 현재 값을 먼저 확인한다. 날짜 판정은 실행 당일 기준으로 그 값에 맞춰 하며, 문서 기본값은 90일이다.

## 결과를 보내는 형식

문서 안의 빈칸은 진행 중 메모용이다. 최종 회신은 아래 코드블록처럼 **항목별 한 줄**로 보내면 된다. FAIL이면 재현 순서와 화면 문구를 함께 적고, UNKNOWN이면 막힌 준비 조건을 적는다.

```text
I-1 PASS — 승인 대기 유지, /dashboard 접근 차단, 로그아웃 가능
I-2 UNKNOWN — 최근 입사일 테스트 계정 준비 불가
I-3 FAIL — 승인 후 대상 계정 새로고침 시에도 대기 화면 유지
I-4 PASS — 반려 후 두 날짜 입력칸 모두 비어 있음
```

사용자 결과를 받은 뒤에만 마스터 체크리스트와 QA 보고서에 반영한다. 결과가 코드 결함을 가리키면 해당 항목만 재현하고 자동 테스트를 추가로 실행한다.
