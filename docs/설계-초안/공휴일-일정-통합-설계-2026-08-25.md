# 공휴일 API·캘린더 일정 통합 설계

> 작성일: 2026-08-25 (KST) · 기준 브랜치: `design/cobalt-glass-redesign`

## 외부 API 확인

기존 `HolidayApiClient`가 사용하는 data.go.kr 특일 정보 API에 테스트 키로 2026년 조회를
실행했다.

- HTTP: `200`
- API resultCode: `00 / NORMAL SERVICE.`
- 응답 공휴일: 22건
- 응답 형태: `response.body.items.item` 배열, `isHoliday=Y`만 저장
- 키 원문은 이 문서·소스·로그·DB에 기록하지 않는다.

## 저장 구조

```text
HOLIDAY_API_KEY ──(앱 기동 시)──> AES-GCM 암호화
                                      │
                                      ▼
                         holiday_api_credentials
                         provider=DATA_GO_KR
                         encrypted_api_key=<암호문>
                                      │
                                      ▼
data.go.kr ──> holidays(date, name, year) ──> HOLIDAY 캘린더 이벤트
```

핵심은 API 키와 공휴일 날짜를 분리하는 것이다. 키는 제공자별 한 행만 가지며 날짜마다
대입하지 않는다. `HOLIDAY_CREDENTIAL_ENCRYPTION_KEY`는 DB와 다른 비밀 저장소에서
주입해야 한다. 최초 시드 때만 `HOLIDAY_CREDENTIAL_SEED=true`를 함께 주입해 앱을
한 번 기동하고, 저장 후에는 플래그를 끈다. 기본값이 false라 이후 환경변수가 DB 키를
덮어쓰지 않는다. DB에 저장된 암호문을 읽을 때는 DB 키를 우선하고, 암호화 설정이 없는
개발 환경에서만 `HOLIDAY_API_KEY`를 fallback으로 사용한다.

## 캘린더 화면 설계

### 데스크톱

```text
┌──────────────── 날짜 칸 ────────────────┐
│ 20             공휴일                    │
│ [공휴일] 광복절                          │
│ [연차] 홍길동  [개인 일정] 출장           │
│                 📅 ...더보기             │  ← 3건 초과 시
└────────────────────────────────────────┘
```

- 공휴일은 빨간 계열(`danger`)의 일반 이벤트로 렌더링한다.
- 공휴일도 일정 개수에 포함하므로 같은 날 공휴일 + 일정 2건을 넘으면 `...더보기`가 뜬다.
- 상세 모달에는 공휴일·연차·개인 일정을 같은 목록으로 표시한다.

### 모바일

```text
┌────── 20 ──────┐
│  •  •  •       │  ← 공휴일도 빨간 점 하나
└────────────────┘

20 수요일                         + 추가
────────────────────────────────────
🔴 광복절              공휴일
🟣 출장                홍길동
────────────────────────────────────
       8월 20일에 추가                         ＋
```

- 셀 안에는 텍스트 대신 일정 종류별 색 점을 표시한다.
- 선택 날짜 하단 요약에 공휴일도 일반 일정 행으로 표시한다.
- 모바일에서는 `...더보기`를 사용하지 않는다.

## 연차·장애 처리

- 공휴일 날짜는 기존처럼 연차 신청을 차단한다.
- 개인 일정 등록은 공휴일에도 허용한다.
- API 키 누락·외부 장애·`resultCode` 비정상 응답 시 캘린더는 빈 공휴일 목록으로 계속
  렌더링하고 WARN을 남긴다. 외부 호출은 긴 DB 트랜잭션을 붙잡지 않는다.
- 이미 DB에 저장된 연도는 외부 API를 다시 호출하지 않는다. 관리자의 강제 동기화만 재호출한다.
