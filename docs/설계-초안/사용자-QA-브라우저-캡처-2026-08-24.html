자동 관찰 증거

  • 로그인 화면 /login에서 연차ON 제목과 Google 로그인 버튼 확인.
  • Google 로그인 버튼 후 accounts.google.com OAuth 화면 진입 확인.
  • 로그인 없는 API가 401을 반환하는 인증벽 확인.
  • Windows 보안 키 창은 Google 패스키 절차이며 앱 토큰이 아님.

주의: 실제 OAuth 계정 없이 인증 이후 화면을 PASS로 확정하지 않습니다. 임의 토큰이나 가짜 authorization code를 사용하지 않습니다.

상세 증거: docs/설계-초안/캡처-2026-08-24/증거-01~04

사전 조건

  • 완료된 관리자 계정 1개, 별도 온보딩 대기 계정 2개, 자동 승인 기간 안의 계정 1개.
  • 실제 @mlsoft.com Google Workspace 테스트 계정 또는 테스트용 OAuth 계정.
  • Google 패스키가 요구되면 실제 키를 사용하거나 취소. 가짜 토큰·쿠키 금지.
  • 계정과 개인정보를 캡처할 때 이메일·토큰·쿠키를 가림.

온보딩·권한

I-1 자동 승인 기간 밖 신규 가입

  1. 계정 A로 로그인하고 기간 밖 입사일로 가입 제출.
  2. 대기 안내와 수정 버튼을 확인하고 dashboard 직접 진입을 시도.

기대: 대기 상태 유지와 dashboard 접근 차단.

I-2 자동 승인 기간 안 신규 가입

  1. 계정 B로 정책 범위 안의 입사일을 제출.
  2. 대기 화면 없이 dashboard로 이동하는지 확인.

기대: 자동 승인과 기준 연차 계산.

I-3 관리자 승인 / I-4 반려 후 재제출

  1. 관리자로 대기 계정을 찾아 제출 정보를 확인하고 승인.
  2. 다른 대기 계정은 반려하고 대상 계정에서 값 초기화와 재제출을 확인.

기대: 승인 기록과 상태 전환, 반려 후 안전한 재제출.

핵심 화면

C-1 캘린더 일정 다건 모달

  1. 여러 일정이 있는 날짜를 찾음.
  2. +N 또는 상세 동작을 열고 전체 목록·긴 사유 모달을 확인.

기대: 한 날짜의 전체 일정과 상세 내용 확인.

C-2 대시보드 개인 일정

  1. 개인 일정이 있는 계정으로 dashboard 진입.
  2. 가장 가까운 일정의 종류·날짜·시간과 hover 상세를 확인.

기대: 본인 일정만 보이고 시간·세부 내용이 표시.

C-3 팀 정보 미배정·팀장 표시

  1. 실제 부서가 없는 임시 계정과 개발팀 팀장 계정을 각각 확인.
  2. unassigned 상태와 leader 표시가 데이터와 일치하는지 확인.

기대: 지정된 팀장은 이름으로 표시되고, 실제 미지정 부서만 미지정으로 표시.

C-4/C-5 연차 Contribution Calendar

  1. 내 정보와 팀 관리에서 연도 선택.
  2. 승인 연차만 표시되는지, 색 농도·툴팁·주말·공휴일을 확인.
  3. 팀 화면에서는 날짜별 승인 사용 인원 수를 확인.

기대: 승인 완료 기록만 개인 일수 또는 팀원 수로 정확히 표시.

C-6 정책 미저장 경고

  1. 정책 값을 바꾸고 저장하지 않은 채 다른 메뉴로 이동.
  2. 경고에서 남기기·이동하기를 확인하고 저장 후 경고 해제를 확인.

기대: 변경 손실 전 명확한 경고와 저장 후 상태 해제.

모바일

M-1/M-2 하단 시트와 모바일 캘린더

  1. 모바일 폭에서 모달을 열어 배경 일부, 아래에서 위로 올라오는 동작, 내부 스크롤을 확인.
  2. 정사각형 날짜 칸과 날짜별 일정 표시를 확인.
  3. 연차 신청의 날짜 선택 화면에서 캘린더 전체를 보고 선택 후 신청 화면으로 복귀.

기대: 화면 전체를 가리지 않는 하단 시트와 자연스러운 날짜 선택 복귀.

M-3/M-4 관리자 화면·키보드 이동

  1. 모바일 부서 관리·관리자 설정의 조회·수정·저장과 미저장 경고를 확인.
  2. 데스크톱 캘린더 화살표와 키보드 방향키 월 이동을 확인.

기대: 모바일 핵심 관리 동작과 명확한 캘린더 이동.
